# Web UI — two front-ends over the same core.py:
#   app_custom.py     Gradio      (local; has the .py uploader + draw canvas)
#   streamlit_app.py  Streamlit   (what Streamlit Community Cloud deploys)
# Installing both is only for running both locally. If you deploy to Streamlit
# Cloud and want a faster/slimmer build, drop the gradio line — streamlit_app.py
# never imports it.
gradio>=6.0
streamlit>=1.50          # width='stretch' on st.pyplot / st.data_editor

# Draw-a-trajectory canvas for the Streamlit app. Optional: without it that one
# control hides itself. Do NOT pass background_image= to st_canvas — that path
# calls streamlit.elements.image.image_to_url, which current Streamlit no longer
# has. Plain canvases work fine.
streamlit-drawable-canvas

numpy

casadi

# Second EKF/UKF implementation (engine/dynamax_filters.py), selected by the
# "EKF / UKF implementation" control in the Estimators section — the same
# estimation problem run through a third-party filter, as a cross-check on this
# repo's own. Pulls in JAX, so it is the heaviest line here; the app degrades
# gracefully without it (the control falls back to the NumPy filters and says
# so in the status line), which makes this a safe line to drop from a slim
# Streamlit Cloud build — streamlit_app.py pins the NumPy backend anyway.
#
# Installing into an EXISTING env can want to bump numpy/scipy under compiled
# packages that were built against the old ones; add
# `numpy==<current> scipy==<current>` to the pip command there to hold them.
#
# Note: dynamax depends on tfp-nightly (tensorflow-probability's nightly), so
# this line makes the build depend on a moving target — pin dynamax and
# tfp-nightly when you cut a release.
dynamax

# The compute engine's package. Installed straight from the upstream repo so
# this Space/repo stays self-contained. Pin to a commit/tag for reproducibility
# once you cut a release.
pybounds @ git+https://github.com/vanbreugel-lab/pybounds.git
